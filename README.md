# morok-web

Веб-клієнт Morok. Він же основа для десктопної збірки (Tauri).

**Це робоча пам'ятка.** Те, що забувається за півроку.

---

## Стек

React 18 · Vite · Tauri 2 (Windows) · Capacitor (лишився з попередньої
мобільної спроби, зараз мобілка живе в `morok-rn`)

Уся криптографія на клієнті, релей бачить лише шифротекст.

---

## Структура

```
src/lib/       крипта, сховище, мережа, логіка
src/screens/   екрани
src/App.jsx    роутинг (хеш-роути) + обробка WS-подій
public/        статика, _headers, manifest
```

Спільні з `morok-rn` файли — правити треба в **обох** репозиторіях:
`crypto.js`, `messages.js`, `groups.js`, `contacts.js`, `dms.js`,
`conversations.js`, `group_storage.js`, `sealed_tokens.js`, `inbox.js`,
`username.js`, `display.js`.

Розсинхрон між клієнтами давав найбільше багів: фіча є в одному,
відсутня в іншому, або та сама логіка поводиться по-різному.

## Деплой

Збирається локально й копіюється **на обидва релеї**:

```powershell
npm run build

scp -r dist/* root@62.238.28.107:/var/www/morok-web/
ssh root@62.238.28.107 "chmod -R a+rX /var/www/morok-web/"

scp -r dist/* root@167.86.120.176:/var/www/morok-web/
ssh root@167.86.120.176 "chmod -R a+rX /var/www/morok-web/"
```

Nginx віддає статику напряму — перезапускати нічого не треба.

**`chmod` обов'язковий.** `scp` створює файли з правами `600`, nginx
працює від `www-data` і віддасть 403.

**Перевіряти з Ctrl+Shift+R.** Service worker тримає старий бандл, і
звичайне оновлення покаже стару версію. Тестувальники побачать зміни
не одразу — у когось при наступному відкритті, у когось за кілька годин.

**Старі бандли не видаляються.** Vite дає файлам імена з хешем, тож у
`assets/` накопичується сміття з минулих деплоїв. Чистити можна, але
**тільки після** успішної заливки.

## Дві збірки, різні base

```powershell
npm run build        # base "/web/"  → для релеїв
npx tauri build      # base "./"     → для Windows
```

**Не плутати.** Tauri-збірка на релеї не працює (шляхи ламаються) — і
навпаки.

## Підводні камені

**`@noble/curves` v1 не має `ed25519.keygen()`** — це API v2. Правильно:
`ed25519.utils.randomPrivateKey()` + `getPublicKey()`. Через цей виклик
анонімна відправка через burner була зламана.

**WebSocket: не відкривати з `token=null`.** Релей одразу відкидає, і без
backoff це вічний цикл на максимальній швидкості — саме він плодив
ghost-слоти в Redis. Guard у `api.openInboxSocket()`.

**Ack тільки після успіху.** Якщо `fetchBlob` не пройшов через мережу —
конверт ack-ати НЕ МОЖНА, інакше повідомлення зникає назавжди. Див.
`__retry` в `messages.js` і `App.jsx`.

**Хеш-роути мають збігатися між клієнтами.** Запрошення до групи —
`#join?t=`; RN колись генерував `#join-group?t=`, і посилання не
відкривались ні там, ні там.

## Локальна перевірка перед деплоєм

- створити акаунт, написати собі з іншого профілю
- burner-лінк: створити й надіслати анонімне
- DevTools → Network → Offline на кілька секунд: у консолі має бути
  `envelope deferred (network)`, після повернення мережі повідомлення
  має дійти, а не зникнути
