# Morok для браузера і Windows

Веб-клієнт месенджера [Morok](https://morok.app) — React і Vite. Той самий
код збирається у застосунок для Windows через Tauri.

Обліковий запис створюється у браузері: пара ключів Ed25519 і мнемонічна
фраза з 24 слів. Ні номера телефону, ні пошти. Приватний ключ не залишає
пристрій.

Серверна частина: [morok-relay](https://github.com/morok-app/morok-relay).
Android: [morok-rn](https://github.com/morok-app/morok-rn).

---

## Що вміє

Те саме, що й мобільний клієнт: приватні чати й групи, вкладення й
голосові, зникомі повідомлення (за таймером від надсилання і від
прочитання), звірка ключів через safety number і QR, PIN із duress-кодом,
анонімні листи за одноразовим посиланням, цифровий заповіт, пошта
morok.email, зашифровані резервні копії, вибір релея й підтримка onion.

Що є саме тут, бо це десктоп:

**Двопанельний режим** на екранах від 900 пікселів — список чатів і
листування поруч.

**Швидкий перехід** Ctrl+K, перетягування зображень у вікно, вставка з
буфера через Ctrl+V, контекстне меню на повідомленнях.

**PWA** — застосунок можна встановити з браузера.

**Windows-версія** через Tauri: згортання в трей, автозапуск, системні
сповіщення.

## Розробка

```bash
npm install
npm run dev
```

Збірка веб-версії:

```bash
npm run build
```

Windows-застосунок (потрібен Rust):

```bash
npx tauri build
```

Базовий шлях перемикається автоматично: `/web/` для сайту, `./` для
Tauri.

## Структура

```
src/screens/      екрани
src/components/   спільні компоненти
src/lib/          логіка: крипта, мережа, сховище
src-tauri/        обгортка для Windows
```

Найважливіше в `src/lib/`: `crypto.js` (Ed25519, X25519,
XChaCha20-Poly1305, Argon2id, BIP39), `messages.js` (формування й розбір
конвертів), `inbox.js` (WebSocket і догін пропущеного), `vault.js` (PIN і
сховище ключів).

Частина файлів у `lib/` спільна з мобільним клієнтом і має збігатися
майже байт-у-байт — розходження там означає баг в одному з клієнтів.

## Від чого захищає і від чого ні

Про межі варто говорити прямо — інакше людина розраховує на захист,
якого немає.

**Вміст повідомлень.** Чати, групи, вкладення, голосові та листи
Morok→Morok шифруються на пристрої. Релей бачить шифротекст і не має
ключів. Ключі виводяться з мнемонічної фрази, яка не залишає пристрій.

**Метадані.** Релей мусить доставити конверт, тому бачить, кому і коли
його віддати, а також IP-адресу з'єднання. Sealed sender ховає
відправника від релея, але не приховує самого факту доставки. Хто, з ким
і як часто спілкується — при постійному спостереженні за релеєм
частково відновлюється. Якщо це має значення, відкривайте клієнт через
Tor або підніміть власний релей.

**Forward secrecy поки немає.** Ключі не змінюються від повідомлення до
повідомлення. Компрометація мнемонічної фрази дає доступ до перехопленої
раніше переписки, якщо хтось її зберігав. Це наступне в планах.

**Пристрій.** Якщо на ньому шкідливе програмне забезпечення або хтось
має фізичний доступ до розблокованого екрана, шифрування не рятує — воно
захищає дані в дорозі, а не від того, хто вже сидить поруч. У браузері
без встановленого PIN мнемонічна фраза лежить у сховищі сторінки
відкрито: розширення браузера прочитає її. PIN шифрує сховище через
Argon2id — встановіть його.

**Зовнішня пошта.** Листи на Gmail та інші адреси йдуть звичайним SMTP
із TLS. Наскрізного шифрування там немає й бути не може — про це
попереджає сам інтерфейс.

**Анонімні листи за посиланням.** Відправник не має способу звірити
ключ отримувача, бо звіряти нічим — на відміну від звичайного чату з
safety number. Недобросовісний релей теоретично може підставити свій
ключ. Для чутливого — звичайний чат із верифікацією.

**Юрисдикція і хостинг.** Публічні релеї стоять у Фінляндії, домен і
CDN — зовнішні сервіси. Хто дивиться на трафік до релея, бачить факт
з'єднання. Проєкт федеративний саме тому: власний релей знімає це
питання.

**Аудиту не було.** Код відкритий, читайте самі — але незалежної
перевірки криптографії третьою стороною поки не проводилось. Це бета.
